# Context format

Follow an existing project format first. Otherwise use a root `CONTEXT.md` for
one context, or a `CONTEXT-MAP.md` pointing to each context's glossary and its
relationships when multiple contexts already exist.

```markdown
# Ordering

The domain that receives and tracks customer orders.

## Language

**Order**: A customer's request for a specified set of products.
_Avoid_: Purchase, transaction

**Customer**: A person or organization that places orders.
_Avoid_: Buyer, account
```

Keep definitions to one or two sentences. Include domain concepts rather than
general programming terms. Group related terms only when useful. Create files
when resolved terminology needs recording and documentation edits are authorized.
